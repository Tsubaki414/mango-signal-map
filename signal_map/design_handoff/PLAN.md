# Mango Signal Map · 开发计划 v2

> 目标：一条链接，任何项目方打开都能在 20 分钟内配出一份属于自己的、可解释的传播阵容，并在客户会议上产生"这很专业"的判断。
> 本文件是重做的施工图。上一版原型的问题：入口写死 iLands、视觉未从官网提炼、logo 未使用、页面像通用后台。以下逐项纠正。

## 1. 产品原则（不变，作为验收标准）

1. 客户只表达偏好，不做研究。每一步都问"这是客户独有的偏好，还是把 Mango 的工作推给了客户？"
2. 每个选择必须在 300ms 内改变可见结果（候选数、平台构成、预算区间、圈层覆盖）。
3. 每个数字可展开成一句话解释；不确定的信息用独立状态标签，不混进分数。
4. 客户端不出现：联系方式、底价、内部人名、触达等级、谈判记录。价格只显示档位。
5. 无真实关系数据不画关系；三种数据状态自然降级。
6. 一个链接服务所有项目方；项目差异全部来自配置，不来自代码分支。

## 2. 设计语言：从 mangolabsglobal.com 提炼

### 2.1 官网首屏实测特征（来源：你提供的 1440 截图 + 站点内容结构 + logo）
- **色彩基调是深青，不是纯黑**：首屏为 `#2E5B5E → #1C3A3D` 的深青大气层，顶部一条 `#0E0E0E` 黑条；文字骨白 `#F3F1EA`；唯一暖色来自画面（橙红余晖），UI 本身不用暖色。产品据此定：**主场深青 `#1F4144`（页面底）/ 更深 `#152F31`（面板）/ 黑条 `#0E0E0E`（顶栏）**；骨白阅读区 `#F3F1EA` 用于名单与确认页；强调色取自站点青调提亮 `#5FC4BB`，暗底文字用；警示暗金 `#C9A227`。不用渐变按钮、不用紫、不用玻璃。
- **两套字体并置**：标题/正文是一款**几何无衬线**（近 Inter/Helvetica Now，字重轻 300–400，紧字距）；**所有导航、标签、按钮、斜杠标签流都是等宽大写**（`ABOUT US` `NARRATIVE ARCHITECTURE / GROWTH CATALYSTS`）。产品沿用：中文正文 **Noto Sans SC 300/400/700**，英文与数字 **Inter 300/400**，所有 UI 标签/按钮/编号 **JetBrains Mono 大写 + .08em 字距**。
- **标题句法**：斜体粗体的引子 + 常规字重的长句（"*Mango Labs,* a global media-tech group at the frontier of what's next."）。产品标题采用同一句法：**斜体粗体的项目名或关键词 + 轻字重陈述**，例如 "*iLands，*想被 AI 研究者和风险投资人看见。"
- **按钮**：矩形、1px 半透明描边、深色半透明底、等宽大写、内边距大（约 22×44）。无填充主按钮；强调靠位置和箭头。
- **斜杠标签流**：等宽大写、` / ` 分隔、单行、无 chip 边框，作为页脚式信息条。
- **编号叙事**：`01 / 02 / 03 / 04` 分节，`01 /// 04` 翻页；`///` 为站点专属分隔符。
- **成果三段式**：`80x pool fill speed · 45% PayFi mindshare · Binance #70`。
- **画面**：全幅电影感环境图（地平线、发光圆环、行人剪影）。产品不放置商业图库，但在首页与揭示页用**同类构图**：低地平线、一道细光环/细线、大量留白；由 CSS/SVG 线条完成，不用位图。
- **Logo**：骨白球体被水平信号带切开、切口阶梯偏移 → **全站图形母题**（分节装饰、加载、空态、进度）。顶栏组合为 mark + `MangoLabs` 常规字重无空格，与官网一致。
- **形**：直角、无阴影、hairline 分隔 `rgba(243,241,234,.16)`；骨白页用 `#D9D6CC`。

### 2.2 字阶（1440 基准，clamp 到 1920）
| 角色 | 规格 | 用途 |
|---|---|---|
| Display | 72/1.08, -0.02em, 300（引子 700 italic） | 首页标题、阶段大标题 |
| H1 | 44/1.15, -0.01em, 300（引子 700 italic） | 分节标题 |
| H2 | 24/1.3, 500 | 卡片组标题 |
| Body | 16/1.7, 300–400 | 说明文 |
| Mono-L | 56 mono 400 | 脉搏大数字、适配度 |
| Mono-M | 13 mono 大写 .08em | 按钮、导航、筛选 |
| Mono-S | 11 mono 大写 .1em | 编号、eyebrow、状态标签、斜杠流 |

### 2.3 栅格与间距
- 12 栏，外边距 56px（1440）/ 80px（1920），栏距 24px。
- 垂直节奏 8 的倍数；分节间距 96px；组内 24px。
- 所有"表格感"的内容用 `1px` hairline 网格（grid + gap:1px + 背景色为线色）实现，不用 border-collapse。

### 2.4 组件规范（全部直角、无阴影）
- **按钮**：与官网一致——矩形、1px `rgba(243,241,234,.35)` 描边、`rgba(0,0,0,.25)` 底、等宽大写 13px、内边距 22×44；hover 描边变实、底变 `rgba(243,241,234,.08)`。主次仅靠位置与右端 `→` 区分；骨白页上描边为 `#141414`。
- **选择卡**：默认 hairline；选中态青色描边 + 左上角 `■`；"最想进入 / 也很重要 / 不优先"三态用实心 / 描边 / 灰。
- **状态标签**（不进分数）：`已确认`（青）`待复核`（暗金）`待补充`（灰）`可对接`（骨白描边）。
- **档位**：`$ $$ $$$ $$$$` 等宽字体，后跟中文档位名。
- **分数**：整数，等宽字，青色；旁 9px 说明"本项目适配度"；点击展开。
- **信号带**（母题组件）：一组 2px 水平线，带阶梯偏移，用于分节装饰、加载态、空状态、进度。
- **空状态**：信号带 + 一句话 + 一个动作。
- **加载态**：信号带逐条点亮；不用 skeleton 灰块。

### 2.5 动效
- 只做三类：数字滚动（脉搏）、hairline 划入（分节出现）、连线描边（关系图 stroke-dashoffset）。
- 时长 200–400ms，`cubic-bezier(.2,.8,.2,1)`；无弹跳、无模糊。
- 生成揭示：3 步文字逐行出现（"理解了你的选择" → "从 262 位有报价的创作者中筛出 41 位" → "为你组成 8 人阵容"），共 2.4s，可跳过。

### 2.6 Logo 用法
- 顶栏：`assets/mango-mark.png` 28px + `MangoLabs` 常规字重（与官网同构）+ 细分隔 + `SIGNAL MAP` 等宽大写。骨白页用 `mango-mark-dark.png`。
- 首页与揭示页：mark 的条纹几何抽成 SVG「信号带」，放大为地平线上的发光细线构图（呼应官网圆环），不直接放大位图。
- 信号带母题的水平线间距 = mark 条纹间距比例（约 1:1.1）。

## 3. 信息架构与页面（一条链接，所有项目方）

### 3.0 入口分流（核心修正：已对接客户不被问赛道）

Mango 与客户的关系有三种，入口必须分别对待：

| 客户状态 | 如何到达 | 打开后看到 | 绝不出现 |
|---|---|---|---|
| **A. Mango 已对接、已建项目**（主要场景） | Mango 发送 `signal.mangolabs.com/p/<token>`（或客户邮箱登录） | **「Mango 对你的理解」页**：项目名、一句话定位、领域、阶段、市场、本次目的、上次沟通要点——全部预填，可逐项改；一个按钮 `继续配置阵容 →` | 任何"你属于什么赛道"式问题 |
| **B. 已对接但本次是新项目 / 新 campaign** | 同上链接进入后点 `为新 campaign 配置` | 沿用客户档案（领域、市场、品牌偏好），只问**本次**变量：目的、预算、本次想进入的圈层 | 重复填公司信息 |
| **C. 陌生访客**（官网 Get Started 带过来） | 通用链接 `/` | 4 问起点：领域 → 市场 → 一句话 → 目的（≤60s） | 强制填 brief |

实现：一条链接，`token` 决定分流；无 token → 显示两个入口：`我有 Mango 项目链接 / 邮箱` 与 `我是新访客`。所有"Mango 已知信息"来自 `GET /api/projects/:token`，前端只做"确认与微调"，不做"采集"。

```
/                       首页：品牌叙事 + 分流（有 token 直接跳 /understand）
/p/<token>              → /understand   Mango 对你的理解（预填，可改，一键继续）
/start                  陌生访客 4 问起点
/configure              偏好配置（一屏一问，滚动叙事，右侧脉搏常驻；已知项默认折叠为已选摘要）
/reveal                 生成揭示（2.4s 仪式）
/lineup                 推荐名单（编辑式目录）+ 我的名单
/lineup/:kolId          KOL 详情（右侧抽屉，可分享 URL）
/overview               阵容价值：路径图 / 覆盖矩阵 / Root 卡 / 变化记录
/confirm                初步阵容确认 + Mango 下一步
```
单页应用，用 hash 或 history 维护；刷新回到同一处；所有状态存 `localStorage['msm:<projectId>']`，接 API 后同步到 `PUT /selection`。

### 3.1 首页 `/`（无 token 时才显示；有 token 直接进 /understand）
- 全屏深青大气层，低地平线 + 一道由信号带构成的发光细线（CSS/SVG）。顶栏黑条：mark + `MangoLabs` · `SIGNAL MAP`；右侧等宽大写导航。
- 标题沿用官网句法："*Mango Signal Map，*让重要的人，看见你。" 引子斜体粗、后句 300 字重。
- 底部等宽大写斜杠流：`AI / CRYPTO / FINTECH · 中文 / EN / 跨境 · X / YOUTUBE / PODCAST / NEWSLETTER`
- 两个描边按钮：`我有 MANGO 项目链接 →` `我是新访客 →`。
- 首屏之下一段 `01 / 02 / 03` 三步说明（表达偏好 → 形成名单 → Mango 执行），每步一句。数字来自 `GET /api/meta`。

### 3.1b Mango 对你的理解 `/understand`（A/B 类客户的真正入口）
- 骨白页。eyebrow `01 /// MANGO 对你的理解`。标题："*iLands，*这是我们目前对你项目的理解。"
- 一张 hairline 表：项目名 / 一句话定位 / 领域 / 阶段 / 主要市场 / 本次目的 / 上次沟通要点。每行右端 `修改`，行内编辑。
- 底部：`确认，继续配置阵容 →`；次级 `这是一个新 campaign`（进入 B 流程，只问本次变量）。
- 文案明确："以上来自我们此前的沟通，不需要重新填写；有出入直接改。"

### 3.2 陌生访客起点 `/start`（四问，一屏一问，Enter 前进；A/B 客户不经过此页）
1. 你的项目属于？——AI / 加密 / 金融 / 科技 大卡（决定 Root 库与圈层示例）
2. 主要市场？——多选 6 个
3. 一句话介绍 + 官网（可空）
4. 本次最想解决？——行业可信度 / 扩大声量 / 产品试用 / 投资人关注
→ 生成项目草稿，进入配置。全程 ≤ 60s。

### 3.3 偏好配置 `/configure`
- 左 8 栏滚动，每题一屏高（`min-height: 80vh`），题号 `2.1 … 2.6`，滚动到位时 hairline 划入。
- 右 4 栏脉搏 sticky：`41` 大数字 + 上一步变化说明（"新增 7 位双语创作者"）+ 平台条 + 档位构成条 + 预算区间 + 圈层 chips + 前 5 名。
- **已知项折叠**：A/B 客户已在 /understand 确认的领域与市场，在配置页显示为一行"已选摘要 · 修改"，不再作为整屏问题；只把本次才需要的问题（人群、Root、平台、预算、品牌偏好）展开成屏。
- 题目顺序：领域细分（陌生访客才展开）→ 想影响的人群 → 想被哪种 Root 看到（类型三态；代表人物点开卡片：是谁 / 行为习惯 / 为什么重要）→ 平台与形式（只显示有报价的平台，其余标"待接入"）→ 预算与档位偏好 → 内容与品牌偏好。
- 每题可跳过；顶部进度线显示 6 段。
- 底部常驻 `查看推荐名单 (41) →`。

### 3.4 生成揭示 `/reveal`
- 近黑全屏，信号带逐条点亮；三行文字逐行出现（见 2.5）；最后一行是"系统对你的理解"陈述句 + 数字摘要（人数 / 预算区间 / 平台 / 语言 / 角色 / 已确认 / 待核验）。
- 点击任意处或 2.4s 后进入名单。只在首次和偏好大改后触发；微调不重复播。

### 3.5 推荐名单 `/lineup`（骨白）
- 顶部：理解陈述（H1）+ `返回调整`。
- 筛选行：搜索 / 平台 / 档位 / 角色 / 只看已确认报价 —— 单行，hairline 分隔。
- **编辑式目录**而非卡片墙：每组一个 `3.x` 标题 + 说明；组内为**两栏横向条目**（头像 · 名称/账号 · 平台/粉丝/类型 · 一句话理由 · 角色标签 · 档位 · 报价状态 · Signal 状态 · 适配度大数字 · 操作）。桌面 1440 一行完整显示，1920 三栏。
- 动态分组（相对当前偏好）：高度符合 / 独特圈层价值 / 预算效率高 / 可补当前缺口（根据我的名单实时计算）/ 媒体与播客 / 值得探索。
- 操作词：`选择` `备选` `对比` `换一个`（弹出 3 个相似替代）`详情`。
- 右 4 栏"我的名单" sticky：人数 / 预算区间 / 方案 A·B 切换 / 已选列表 / 角色 chips / 覆盖行 / 缺口提示 / **刚刚的变化**（黑底青字，说明加入或移除带来的变化和替代建议）/ `查看阵容价值 →`。

### 3.6 KOL 详情抽屉 `/lineup/:kolId`
顺序固定：身份行 → 一句话 → **为什么是 86**（6 条分项条 + 优势 / 限制 / 缺失）→ 被看到 / 被互动双轴（无数据显示"待补充"）→ 报价对应内容形式（形式 + 档位，不显数字）→ 报价状态 / 商务路径 / 记录时间 → 关系 Signal 列表（类型 · 时间 · 次数 · 证据 · 已核验/待核验）→ Mango 判断 → 相似替代（可一键换）→ 底部固定操作。

### 3.7 阵容价值 `/overview`（近黑）
- 头部：陈述句（"8 位创作者，覆盖 3 个平台与 2 个市场。包含 3 位专业解释者…6 位可对接，2 位报价待复核。"）+ Signal 陈述（有数据时）+ 六格数字。
- **4.1 注意力路径图**：四列（你的项目 → 已选 KOL/媒体 → 目标 Root → 目标圈层），HTML 节点 + SVG 连线，实线已核验、虚线待核验；点击 KOL 高亮其路径，点击 Root 显示桥梁，点击连线看证据；右侧检视面板。无数据时整块替换为"覆盖图"。
- **4.2 目标圈层覆盖矩阵**：行 = 所选圈层，列 = 已选 KOL，格 = Signal 数；多人覆盖青、单点暗金、缺口空；无 Signal 数据时降级为"目标人群 × KOL"。
- **4.3 可能进入谁的信息流**：具名 Root 卡（头像位 / 姓名 / 身份 / 为什么重要 / 经由谁），仅列有 Signal 的 Root；无数据时显示 Root 库代表人物并标注"待补充路径"。
- **4.4 变化记录**：本次会话所有增删换的时间线（预算、平台、圈层、角色变化）。

### 3.8 确认 `/confirm`（骨白）
- 初步名单表（编号 / 名称 / 平台 / 角色 / 适配度 / 档位 / 报价状态）。
- 右栏：仍需 Mango 核验（自动生成）/ Mango 接下来会做（四步）/ `确认初步阵容 →` / 次级：返回调整 · 请 Mango 再优化一次 · 保存稍后继续 · 导出方案（打印样式）。
- 确认后：黑底卡片"初步阵容已发送给 Mango…"，明确不是购买。

### 3.9 三种关系数据状态（全站一致）
| 状态 | 配置 | 脉搏 | 分数 | 详情 | 路径图 | 矩阵 | Root 卡 |
|---|---|---|---|---|---|---|---|
| 充分 | 显示 Signal 计数 | 圈层 chips 带计数 | Root 项计入 | 双轴 + Signal 列表 | 完整 | 圈层 × KOL | 有 Signal 的 Root |
| 部分 | 只显示已核验 | 同上 + "部分核验" | 计入已核验 | 已核验 + 提示 | 只画已核验 | 同上 | 同上 |
| 无 | "Signal 待补充" | 无圈层计数 | Root 项置灰不计 | 双轴显示待补充 | 隐藏，显示说明 | 人群 × KOL | 库代表人物 + 待补充 |

## 4. 数据层与接口

### 4.1 前端数据模型（`data/schema.md` 同步维护）
`Project` · `Taxonomy` · `RootLibrary[domainGroup]` · `KOL` · `QuoteLine` · `Tier` · `Signal` · `Selection{prefs, plans, plan, confirmedAt}` · `Submission`

### 4.2 接口（Codex 侧）
| 接口 | 说明 |
|---|---|
| `GET /api/meta` | 全库汇总（首页数字）：有报价 KOL 数、平台、领域 |
| `GET /api/taxonomy` | 市场 / 语言 / 领域 / 人群 / 平台 / 形式 / 档位阈值 |
| `GET /api/roots?domainGroup=` | 对应领域 Root 类型与代表人物 |
| `GET /api/projects/:token` | 已对接客户的项目档案（Mango 理解、上次沟通要点、客户档案偏好）——A/B 类入口的数据源 |
| `POST /api/projects/:token/campaigns` | B 类：沿用客户档案新建 campaign |
| `POST /api/projects` | C 类：陌生访客起点创建草稿项目 |
| `GET /api/candidates?domainGroup=&markets=` | 全库有报价候选（含档位、商务状态、标签、报价形式；**不含**联系方式与原始金额） |
| `GET /api/projects/:id/signals` | Signal；无数据 `[]` |
| `PUT /api/projects/:id/selection` | 保存偏好与名单 |
| `POST /api/projects/:id/submissions` | 提交初步阵容 |

### 4.3 档位计算归属
后端按"单条主内容 USD"分档后直接给 `tier`；前端不接触原始金额。演示期前端用阈值兜底。

### 4.4 评分
`fit = Σ w_i · v_i`，权重：领域 30 / 人群 20 / 市场语言 15 / 平台形式 15 / Root Signal 10 / 预算 10。无 Signal 数据时 Root 项 `pending`。被看到 / 被互动只在有 Signal 时计算。全部逻辑在 `adapter.js`，可被后端同名接口替换。
