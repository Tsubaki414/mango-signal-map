# Mango Signal Map · 设计与产品审计（待批准，未执行）

审计视角：一位顶级产品经理（客户会不会用、会不会误解、会不会流失）+ 一位顶级设计师（是否有品牌记忆点、层级是否清晰、密度与节奏）。
标记：**P0** 会伤害转化或造成误解 · **P1** 明显提升体感 · **P2** 加分项。

---

## A. 产品与流程

**A1 · P0 · 没有"回到上次进度"的可靠入口**
现在刷新会恢复状态，但客户第二次打开链接时不知道进度在哪一步。建议顶栏进度线显示已完成态（打勾 / 填充），并在首页显示"你的 iLands 名单已保留 6 人 · 继续 →"。

**A2 · P0 · 第一次进入没有引导，客户不知道要花多久**
配置页有 6 组问题但没有预期管理。建议顶部加一行"约 4 分钟 · 任何一步都可跳过 · 随时保存"，并在脉搏栏顶部显示"已回答 3 / 6"。

**A3 · P0 · 名单页缺"为什么是这几组"的引导动作**
客户看到 6 组 40+ 人仍会不知从哪下手。建议加一条"Mango 建议起点"：自动预选 6–8 人的推荐阵容，客户从"修剪"开始（这是最初设计原则，目前还是从 0 选）。

**A4 · P1 · 预算没有"实时对照"**
预算选了 $10k–30k，但选人时不会提示超出。建议我的名单里加一条预算刻度条：已选区间 vs 目标区间，超出时变暗金并提示"移除 1 位 $$$ 或改为 $$ 档"。

**A5 · P1 · 判别标准页与名单之间缺少闭环**
客户认可了判别，但名单里看不出"因为你认可了 X，所以这位排在前面"。详情抽屉已有规则说明，建议卡片上也加一枚小标记（如"符合你认可的 3 条判别"）。

**A6 · P1 · 方案 A/B 没有对比视图**
能切换但不能并排比较。建议加"A/B 并排"弹窗：人数、预算、角色、圈层覆盖、缺口五行对比。

**A7 · P1 · 缺少"我不确定"的出口**
客户可能对某人拿不准。建议每张卡加"请 Mango 判断"，进入待核验清单，比逼客户做决定更符合服务定位。

**A8 · P2 · 分享与协作**
客户方常是 2–3 人决策。建议"生成只读分享链接 / 导出 PDF"（导出已有，链接可后端补）。

**A9 · P2 · 提交后没有回执页**
确认后只在原页显示卡片。建议一个独立回执页：提交时间、名单快照、Mango 顾问与预计回复时间。

## B. 信息与信任

**B1 · P0 · 适配度数字缺少"锚"**
看到 68 不知道是高还是低。建议数字旁加分布位置（如"前 15%"）或色阶带，并在名单顶部说明"70 以上为高度符合"。

**B2 · P0 · 报价档位仍可能被误读为最终价**
建议每次出现预算区间处统一加一行极小字"档位区间，非报价；以 Mango 复核为准"，目前只在部分位置有。

**B3 · P1 · "被看到 / 被互动概率"两个数字缺少解释边界**
建议加一句"基于已观察到的公开关系估算，不是承诺"，并在无数据时保持灰字"待补充"（已做）。

**B4 · P1 · 演示数据标注不够显眼**
现在只在首页脚注。建议在名单与阵容页也加一枚 DEMO 徽标（Tweaks 可关）。

## C. 视觉与品牌

**C1 · P0 · Hero 偏简陋（你已指出）**
问题在于：右侧圆环是唯一图形，左侧大量留白无内容，按钮平淡，没有"产品在做什么"的可视证据。三个方案见下节。

**C2 · P1 · 缺少节奏变化，通篇 hairline 网格**
建议引入 2–3 处"全宽深黑分节条"（如揭示页、确认页之间），用 `#0E0E0E` 作节奏分隔，与官网顶栏黑条呼应。

**C3 · P1 · 头像位全部是首字母方块**
真实感不足。建议接入真实头像字段（后端 `avatarUrl`），演示期用 `image-slot` 占位让你拖入。

**C4 · P1 · 数字层级不够戏剧化**
脉搏 64px 已好，但名单页适配度 30px、阵容页 30px 偏平。建议阵容页关键数字提到 48–56px，其余降到 20px，制造对比。

**C5 · P2 · 信号带母题用得不够**
目前只在起点与揭示页。建议用于：分节标题左侧短带、加载态、空状态、确认页页脚。

**C6 · P2 · 中文标点与字距**
大标题里的中文逗号占位偏宽。建议对标题加 `font-feature-settings` 或手动收紧标点前后间距。

## D. 交互细节

**D1 · P1 · 无键盘流**
配置页应支持 数字键选项 / Enter 下一步 / Esc 关抽屉。目前只有焦点环。

**D2 · P1 · 抽屉无 URL**
KOL 详情不能分享。建议 hash 路由 `#/kol/k24`。

**D3 · P1 · 移动端未处理**
客户可能在手机点开链接。建议 <768px：单列、脉搏收为底部条、名单卡单列、路径图改纵向列表。

**D4 · P2 · 无 loading 与错误态**
接 API 后需要：加载中信号带、请求失败重试、Brief 码错误已做。

**D5 · P2 · 动效偏少**
数字变化没有滚动过渡；卡片选中没有微反馈。建议数字 `count-up`、选中时卡片 1px 位移。

## E. 工程与交付

**E1 · P1 · 判别标准接入排序目前是关键词匹配**
演示可用，正式版应由后端把 criteria 编译为规则 id（已在 API 文档注明）。

**E2 · P1 · 英文版未完成**
只做了部分界面文案。建议 taxonomy 与 Root 库都带 `label_en`，前端按 `uiLang` 取。

**E3 · P2 · 无埋点**
建议约定事件：进入各阶段、每次偏好变更、保留/移除、判别认可、确认提交，便于 Mango 侧观察客户卡在哪。

## Hero 三个方案（待你选）

**方案 A · 信号地平线**（已建 `Hero A · 信号地平线.dc.html`）
Logo 的球体放大成"半沉的日轮"，被四条粗信号带切开，落在近黑地平线上；地平线下细带缓慢横移。标题左对齐大字，右侧留给图形。品牌辨识度最高，最像官网延伸。

**方案 B · 活的路径图**
Hero 右半直接展示产品核心画面：项目 → 创作者 → Root → 圈层 的四列路径图，进场时连线自描、节点逐个亮起。客户第一眼就看懂产品在做什么，转化最强。

**方案 C · 名字墙**
Hero 背景是缓慢横移的两行真实 Root 名字（Andrej Karpathy · Sam Altman · Marc Andreessen…），前景一句"他们的信息流，不是买得到的"。冲击力最强，但需确认可否公开展示这些名字。
