# iLands 对照审计 · v3 的内容缺口

读完 iLands 那份的四屏全部内容后的结论：**我们的框架是对的，但内容密度差了一个量级。**
iLands 每一条记录都是手写的、带具体数字和可查证据；我们的是程序生成的标签。这就是"还没有别人随手做的 demo 丰富"的真正原因——不是缺功能，是缺**判断**。

---

## 一、Dov 到底想要什么（从这份 demo 反推）

1. **target-backed KOL discovery**：目标人先行，用他们的共同关注反推可投放的人。这是整套方法的名字，也是唯一的差异化。
2. **"可执行"是最高准则**。原话是「客户版只展示可执行路径；不可执行噪声已在内部过滤」。名单不是研究报告，是执行队列。
3. **强关系 ≠ 可投放**。这是整份 demo 最专业的一句话——很多强互动发生在研究者、教授、投资人之间，能证明话题路径，但不能当 paid KOL。
4. **客户能修正判断逻辑**，而且修正会回流到下一轮排序。
5. **商务现实主义**：sponsor 入口、contact、报价、档期、风险标签，每一步都要落地。
6. **不承诺结果**。脚注明确写"不承诺任何 AAA 账号会点赞、回复或转发"。

---

## 二、iLands 有、我们完全没有的（按价值排序）

### 1 · 目标人物的行为画像与内容角度 ★★★ 最大缺口
iLands 每个 root 都有：
```
@karpathy  评论区下场型
采样 30 条 · reply 15 · quote 4 · RT 3 · original 8
战术：找桥接节点在其常回复的话题下发高质量评论，不要只发独立帖等他看见
触发：具体技术判断、可回答的问题、能让他补充或纠正的观点
角度：Survival compute / long-running agents
```
我们只有一句「技术圈公认权威」。
**这才是客户真正想买的东西**——不是"这个人重要"，而是"要怎么做内容他才会接住"。

### 2 · 双轴矩阵：强关系 × 可表达 ★★★
四象限，每格有明确处置方式：
- 强关系 × 可表达 → 下一轮重点：查样张、商业路径、定制 quote angle
- 强关系 × 不宜投 → 用作 topic anchor、二跳路径，**不能当 paid KOL**
- 弱关系 × 可表达 → 低优先级观察
- 关系待验证 × 可表达 → 观察池

我们把"被看到/被互动"双轴删掉了，但删错了地方——该删的是没有依据的百分数，不是这个**分类判断**。

### 3 · 关系强度分级 H0–H3 ★★★
```
H3 多次主动互动，且主题相关   → 优先深挖，但仍需身份和商业复核
H2 反复互动或轻双向互动       → 适合做二跳桥接
H1 单次主动触达或弱互动       → 只能作为补充证据，不单独推荐
H0 暂未补到历史互动           → 不作为关系证据
```
我们只有 verified / 核查中两态，等于把所有关系拉平了。

### 4 · 执行队列 A/B/C/D ★★★
```
A 可优先商务确认  → 问报价、样张、档期、可定制角度
B 需 BD 验证      → 联系方式、接单意愿、历史合作、报价区间
C Warm intro / PR → 走媒体库存，不按普通 paid KOL 处理
D 内部观察        → 不推进
```
明确写着"A/B/C/D 不是最终推荐，而是执行队列"。我们只有「可赞助已确认 / 商务待验证」两个标签，缺了 C 和 D 这两类**处置方式完全不同**的人。

### 5 · 四维筛选器 ★★
分层 / 内容标签（8 种 lane）/ 商务状态（4 种）/ 风险标签（4 种：无 · 研究者学术身份 · 工具号提示词风险 · VC投资人身份）。
我们只有圈层 chip 和搜索。**风险标签**尤其重要——它是"为什么这个人不能投"的答案。

### 6 · 分波策略 Wave ★★
```
Wave 1 · AI/agent 原生 creator   服务行业大佬和垂类专家，先定义产品，不做工具测评
Wave 2 · VC Visibility 媒体播客   服务 VC root，sponsor / warm intro
Wave 3 · Interaction Bridge      服务会下场的专家，优先进入会被回复的评论区
```
每波服务谁、做什么、避免什么。我们的名单是一个平面列表，没有先后。

### 7 · 单个 KOL 的十个字段 ★★
iLands：`persona / tier / axis / fit / seen / interaction / commercial / action / reason / evidence`
其中三个我们完全没有：
- **action**：「先做 BD 验证，不要直接当确认可买的 media-buy」——告诉客户下一步做什么
- **evidence**：「X 约 150K followers；Rohan's Bytes 约 8K subscribers；官网/Substack 暂未发现公开赞助页或商务邮箱」——可查证的复核记录
- **persona**：「AI show / newsletter」「deep AI podcast host」——一句话身份

### 8 · 三个 Gate 的解释卡 ★★
被看到概率 / 被互动概率 / 质量 gate，每个都写「它回答什么问题」。
第三个 gate 尤其好：**评论区回复者质量**——谁在他评论区回复（AI / VC / founder / 研究者）。这是判断一个账号是否真有价值的最强指标，我们完全没有。

### 9 · 判别逻辑四栏（我们删过头了）★★
更想要的人 / 不想要的人 / 还在确认的边界 / 下一轮推荐如何调整 + 可编辑 + 导出偏好 JSON。
你之前要删的是**逐条 Approve/Reject/Question 审核**（对，那个太累），但「Mango 当前如何理解你」这块内容本身是专业感的核心。我现在只留了确认区一段陈述，太薄。

### 10 · 下一轮配比策略 ★
「下一轮名单保持 70% 高匹配、20% 边界确认、10% 探索样本」——一句话就让人觉得这个系统有方法论。

### 11 · 数据脚注 ★
「62 个具名 root、1,429 条近期公开互动边、1,738 个共同关注候选、107 扩池，额外经过近期流量、合作路径、评论区回复者质量三项 gate。用于策略判断，不承诺任何账号会点赞、回复或转发。」
你说 hero 不要这些数字——但放在**页脚**是专业感的来源，不是营销。

## 三、我们比 iLands 好的地方（要保住）

- 客户能**自己选**目标人物并即时看到名单重排；iLands 是交付物，我们是工具
- 单页、渐进展开，不用闯关
- 预算按实际保留的人和合作形式实时汇总
- 真实头像、视觉与官网一致、动效克制
- 关系图可交互

## 四、v3 当前最该补的六件事（建议优先级）

| # | 补什么 | 为什么 | 工作量 |
|---|---|---|---|
| 1 | 目标人物的**行为画像 + 内容角度**（采样/回复/引用/转发 + 战术 + 触发 + 角度） | 客户真正要买的东西 | 中 · 需手写 40+ 人物内容 |
| 2 | 关系强度 **H0–H3** 分级 + 卡片显示 | 让"共同关注"这条主线有分量 | 小 |
| 3 | 执行队列 **A/B/C/D** + 处置方式 | 把名单变成可执行清单 | 小 |
| 4 | **强关系 × 可表达** 四象限视图 | 唯一能体现"专业判断"的一屏 | 中 |
| 5 | KOL 的 **action / evidence / persona** 三字段 | 每条记录从标签变成判断 | 中 · 需手写 |
| 6 | **风险标签** + 四维筛选 + 页脚数据脚注 | 显出方法论 | 小 |

再往后可选：分波 Wave 策略、评论区回复者质量 gate、判别逻辑四栏回归（只读版，不做逐条审核）。
