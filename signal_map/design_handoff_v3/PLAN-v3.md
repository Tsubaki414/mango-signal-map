# Mango Signal Map v3 · 单页工具版 · 改造计划（待批准）

目标：把现在的四阶段闯关流程收敛成**一页**——客户自己选方向 → 看到并调整想触达的人 → 同页拿到 KOL 推荐 → 挑出名单 → 确认交给 Mango。
Dov 的原话是"一整页……你要什么样子的，直接给你生成一个 targets 的目录……根据这些 target 的人的关注列表，找共同子集"。这版就照这个做。

## 1. 新的页面结构（一页滚动）

```
┌ HERO（保留，压缩到一屏）
│  01 /// KOL LINEUP CONFIGURATOR
│  Mango Signal Map，让重要的人，看见你。
│  一句话说明 + [开始选择 ↓]（滚动到工具区，不换页）
└
┌ 顶栏（sticky）：logo · SIGNAL MAP · 项目条 · 锚点「偏好 / 目标人物 / 推荐名单」· 自动保存
│  项目条：有 Brief 时显示「iLands · AI · 美国 ✎」，可改可清空；没有就显示「未命名项目 ✎」，不挡路
└
┌ 工具区（左主 + 右轨，右轨 sticky 随阶段变内容）
│
│  A · 偏好（渐进展开，不一次铺开）
│     A1 领域大卡（AI / 加密 / 金融）→ 选中后才展开该领域的细分方向标签
│     A2 市场与语言（选中领域后出现）
│     A3 想影响的人群（开发者 / 创始人 / 投资人 / 交易者 …）
│     A4 预算（四档 + 「暂时不确定」）
│     [更多偏好 ▾] 抽屉：内容形式、品牌偏好、语气、避雷
│
│  B · 目标人物（这次改造的核心）
│     根据 A 的领域 + 人群，同页列出一组**具体人物卡**：头像 / 名字 / 身份 / 一句为什么值得触达
│     操作：选中（想触达）· 移除（不相关）· 搜索框补充库里其他人
│     顶部一行圈层筛选 chip（创始人 / 研究者 / VC / 开发者领袖 / 媒体），点了只是过滤这组人，不是给抽象类型打优先级

│
│  C · 推荐名单（同页，偏好一变就重排）
│     首次生成：一次 1.2s 可跳过的揭晓（线条 + 数字 + 卡片依次入场），就地展开，不跳页
│     之后改任一条件：卡片重排 + 数字滚动 + 关系线变化，不重播动画、不加等待
│     两段清楚分开：【已保留 N 人】在上，【推荐候选】在下
│     卡片：头像 / 名字 / @账号 / 一句内容方向 / 适配度（带解释）/ 报价或档位 / [保留] [换一个] / [展开 ▾]
│     展开：内容样例、评分依据分项、与目标人物的关系证据（有才显示，没有显示「信息待补充」）
│
│  D · 名单摘要与确认（右轨 + 同页展开）
│     右轨随阶段切换：
│       选偏好时 → 符合条件的 KOL 数、已选圈层与人物
│       挑名单时 → 已保留人数、按实际选中的人汇总的预算、名单构成、[确认这份名单]

│
│  E · 关系图（名单旁的可展开视图，不是必经页）
│     只画「已保留 KOL —— 目标人物 —— 圈层」，点节点高亮、点连线看关系类型/方向/时间/证据
│     有真实数据才画连线；没有就显示按标签与报价筛选的覆盖视图
│     若展示完整效果，整块打上「演示数据」标记
└
```

## 2. 目标人物（Root）的定义与边界
- Root = **客户希望影响的目标人物**，不是可以下单投放的 KOL。文案统一用「想被谁看到 / 目标人物」。
- 客户选目标人物是在**表达需求**，不需要逐条审核人物是否合格。
- 两种路径严格不混用：
  - Mango BD 系统里已有的是「员工 → 供应商/KOL」的**商务路径**；
  - 「KOL → 目标人物」的公开关注与互动路径**尚未建立完整数据**。
- 所以：有真实关系数据 → 显示具体连线与人数；没有 → 只按标签与报价筛选，并明确说明关系数据待补充。绝不把关注关系表述成"这位大 V 一定会看到"。

## 3. 分数与报价的表达
- 适配度：醒目（等宽大字 + 四级色阶），但每次都能展开成「因为你选了 X，所以 Y」的分项解释。
- 依据不足 → 显示「信息待补充」，不编造分数。
- 报价：见下方问题 2（档位 vs 具体价格）。
- 预算汇总：**只按已保留的人 + 其对应合作形式**计算；取消「默认前 8 位 · 每人一条内容」的预估。没保留人时右轨显示「尚未保留任何人」，不显示预算数字。

- 新建 `Mango Signal Map v3.dc.html`（v2 原样保留作存档，随时可对照）。样式、`motion.js`、`gradient-waves.js`、`data/adapter.js` 全部沿用。

## 5. 交付顺序
1. 骨架 + Hero + 顶栏 + A 偏好区（渐进展开）+ 右轨阶段一
2. B 目标人物区（卡片 / 搜索 / 选中移除）
3. C 推荐名单（揭晓 + 保留/换一个 + 展开证据）+ 右轨阶段二
4. D 摘要确认 + E 关系图可展开视图
5. 打磨：窄屏、键盘、对比度、`API-ADAPTER.md` 与交接包更新
