# 砍掉多此一举 · 修订版

> ⚠️ **2026-09-09 重大修正**：候选池不等于"已有报价库"。见文末《修正：这其实是一个发现 + 建联的产品》。
> 本文中"我们的池子本来就是有报价的 KOL，按定义全都能投"这一前提是**错的**，由此砍掉的两条（A/B/C/D、强关系不宜投→加为目标人物）应当恢复。

## 一个共同的毛病

我在把一个**选人工具**装扮成**研究报告**。
Mango 的 KOL 绝大多数就是发推、转推；客户要的只有两件事：

> **这个人能不能把内容送到我想影响的人面前？能不能约到？**

任何不回答这两个问题的层级，都是多此一举。用这把尺子重新量，砍掉的东西比要加的还多。

## v3 现在就存在的多此一举

### 1 · 适配度分数本身可能是多余的
现在一张卡上有四种东西在说同一件事：`86` 分 · 等级词 · 顶部色阶条 · 展开后 5 条分项进度条。
而客户真正要看的那个数字其实是——**与你选的几位有连接**。
把内容契合、人群契合、市场、预算揉进一个综合分，反而**稀释了唯一清晰的信号**。

> **建议**：排序主依据回归"连接数 × 强度"，把内容/人群/市场从分数降级为标签。
> 综合分保留但退到次要位置，或者干脆只在展开时出现。

### 2 · 关系强度不需要四级
我们的演示数据只有 类型（关注/回复/引用/同场）+ 次数 + 是否核验。
硬分 H0–H3 是**在演示数据上伪造精度**。诚实的做法是两级：
- **互动过**（回复、引用、同场）——强
- **只是关注**——弱

一眼能懂，也经得起客户追问。

### 3 · "换一个"按钮
它诞生于"系统给一份固定建议名单、客户修剪"的旧流程。
现在名单是长列表且实时重排，客户不选就是不选，**多一个按钮多一层心智负担**。

> **建议**：删掉。保留"一键采用建议名单"就够了。

### 4 · 方案 A/B 双名单
在一个所有东西都实时重算的单页里，客户想比较只要改选择再看一眼。
双名单要求客户维护两份状态、还要记得当前在哪份。

> **建议**：降级或删除。真要比较，不如做"改动前后对比"一行提示。

### 5 · 品牌偏好那七个 chip
折在"更多偏好"里，对排序影响微乎其微，客户点了看不到变化——**给了控制却没有反馈，比不给更糟**。

> **建议**：删到只剩真正会改变名单的那一两个（例如"避免营销痕迹过重"）。

### 6 · 关系图
好看，但它显示的覆盖信息右轨已经用 chip 说清楚了。它的价值是**演示时的说服力**，不是决策工具。

> **建议**：保留现状，不再投入；明确定位成展示件。

### 7 · 每人的合作形式切换（post / thread / Spaces）
这个我倾向**保留**——它是唯一影响预算的变量，一行按钮，成本极低。但要注意别再往上加"条数"之类的维度。

## 修订后的落地清单

**该做（都小）**
1. 排序主依据回归连接数与强度，综合分降级
2. 关系强度两级，去掉伪精度
3. 证据第一行改成"你选的 X 出现在他评论区 N 次"
4. 风险标签 → 合作方式（可直接洽谈 / 需 Mango 建联 / 媒体与播客路径）
5. 筛选器：合作方式 + 内容标签 + 连接强度（三维，不是四维）
6. 顶部"方法 · 目标人先行，共同关注反推"可点开
7. 移除某人时一句"Jim Fan 将失去唯一连接"

**该删**
8. 换一个按钮 · 方案 A/B · 品牌偏好大部分 chip · 分项进度条降到展开区

**需手写内容、单独一轮**
9. 目标人物的一句话行为特征（"评论区下场型 / 引用转发放大型"）——**只做标签，不做战术手册**
10. KOL 的 persona 一句话身份 + 商务核查记录

## 一句话原则
**每加一个元素，先问：它改变客户的哪个动作？**
不改变动作的，就是给 Mango 自己看的，不该出现在客户页面上。

# 修正：这其实是一个发现 + 建联的产品

## 证据：iLands 的 107 人不是报价库
回头看它的字段就很清楚——

```
@rohanpaul_ai
commercial: "公开 sponsor / contact 未确认"
evidence:   "官网/Substack 暂未发现公开赞助页或商务邮箱"
action:     "先做 BD 验证，不要直接当确认可买的 media-buy"
```

筛选器里的商务状态四态也是同一件事：
`明确 contact / sponsor` · `可走媒体 creator 路径` · `可能可合作，需 BD` · `商务待验证`

**107 人里相当一部分，Mango 当时既没联系过，也没有报价。**
它们是从 1,738 个共同关注候选里筛出来的**发现结果**，A/B/C/D 就是给这批人排的建联优先级。

## 所以产品是两层，不是一层

```
目标人物（客户说想影响谁）
        ↓  取其关注与互动网络的共同子集
发现候选池
        ├── 已在 Mango 报价库 → 可立即确认档期与报价
        └── 尚未建联的新人   → 客户表达兴趣 → Mango 去建联 → 报价回来
        ↓  流量、表达面、可合作性三道过滤
客户可见执行池
```

我们目前的 v3 只做了上面那一半的一半：**只从已有报价库里筛**。
这恰恰漏掉了这套方法唯一真正值钱的地方——
> **"我们不只从手上的资源里给你挑，还会顺着你想影响的人，去找并建联现在还没合作过的人。"**

对客户来说，这句话比任何评分都有说服力；对 Mango 来说，这也是资源库自我扩张的入口。

## 由此要恢复 / 改动的

**恢复**
- **建联优先级分层**（A/B/C/D 的精神，但用人话、只对客户露 2–3 层）：可立即确认 / Mango 去建联 / 走媒体与播客路径
- **"强关系但不接商单 → 加为目标人物"**：新发现的人里真的会有这一类，闭环成立

**新增**
- 名单里**两类候选并存**，且视觉可区分：`已有报价` 与 `新发现 · 待建联`
- 新发现的人：显示**发现依据**（经由哪几位目标人物的共同关注找到），不显示价格，显示"报价待询"
- 客户动作从单一的「保留」分成两种语义：已有报价 → **加入名单**；新发现 → **请 Mango 建联**
- 预算显示改为**两段**：`已知 $12k–18k` + `另 3 位待询价`（诚实，且体现 pipeline）
- 右轨新增一行：`可立即执行 5 位 · 待建联 3 位`

**演示数据要补**
- 现有 54 位来自报价导出（= 已有报价）
- 需再编一批**无报价的发现候选**（真实公众账号，标注为演示），才能演出这套方法

## 关系强度：分三级（按你的意见）
只用我们真实拥有的信号，不伪造精度：

| 级别 | 依据 | 含义 |
|---|---|---|
| **强** | 多次回复 / 引用 / 同场，且主题相关 | 目标人物确实会接住他的内容 |
| **中** | 单次互动，或双向关注 | 有路径，值得推进 |
| **弱** | 仅单向关注 | 作为覆盖补充 |

卡片上直接写"强连接 · 3 位"，不用 H3 这种代号。
