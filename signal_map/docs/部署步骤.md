# Signal Map 上线步骤

写给不看代码的人。照着做就行，每一步都标了「做完应该看到什么」。

整套东西分两半：

- **后端**（数据和接口）→ 放 **Railway**
- **前端**（客户看到的网页）→ 放 **Vercel**

为什么不能都放一个地方：后端有一个 35MB 的数据库文件，需要一块**能一直存着
的硬盘**。Vercel 没有这种硬盘（它每次处理完请求就把机器扔了），所以后端必须
在 Railway。前端没有这个问题，放 Vercel 会更快，放 Railway 也行。

---

## 第一步：后端上 Railway

1. 打开 <https://railway.app>，登录。
2. **New Project** → **Deploy from GitHub repo** → 选这个仓库。
3. 进入这个服务的 **Settings**：
   - **Root Directory** 留空（不要填 `signal_map`）。
   - **Config-as-code** 填 `signal_map/railway.json`。
4. 切到 **Variables**，加两条：

   | 名字 | 值 |
   |---|---|
   | `SIGNAL_MAP_DB_PATH` | `/data/signal_map.db` |
   | `SIGNAL_MAP_ALLOW_DEMO_BRIEF` | `0` |

   第二条很重要：不关掉的话，**任何人在网页上输入 `demo` 就能打开你库里第一
   个项目的简报**（项目名、方向、市场、预算档都会显示出来）。

5. 切到 **Volumes** → **New Volume**，挂载路径填 `/data`。
   这块就是那个「能一直存着的硬盘」。客户的选择、保留的名单、提交记录都存在
   这里。**没有它的话，每次你重新部署，客户的数据就全没了。**
6. 等它构建完（大概 3–5 分钟）。绿了以后，在 **Settings → Networking** 点
   **Generate Domain**，会给你一个网址，长这样：
   `https://xxx-production.up.railway.app`

**做完应该看到什么**：浏览器打开 `那个网址/api/meta`，显示类似

```json
{"kols":276,"platforms":7,"groups":3,"markets":6}
```

看到这行就说明后端活了。**把这个网址记下来**，下一步要用。

---

## 第二步：前端上 Vercel

1. 打开 <https://vercel.com>，登录，**Add New → Project**，选同一个仓库。
2. **Root Directory** 填 `signal_map/frontend`（这个一定要填）。
3. **Environment Variables** 加一条：

   | 名字 | 值 |
   |---|---|
   | `SIGNAL_MAP_API` | 第一步记下来的那个 Railway 网址 |

4. **Deploy**。

**做完应该看到什么**：Vercel 给你一个网址，打开就是 Signal Map 的首页，往下
滚能看到三个领域卡片（AI / 加密 / 金融科技），点一个能出名单。

> 客户的浏览器**看不到** Railway 那个网址 —— 前端在服务器内部转发，所以后端
> 地址不会暴露，也不用处理跨域问题。

---

## 以后要改东西怎么办

**改了网页样式或文案** → 提交到 GitHub，Vercel 自动重新部署，1 分钟左右。

**改了后端代码** → 提交到 GitHub，Railway 自动重新部署。客户数据不受影响。

**库里的数据更新了**（跑完采集、分类、报价录入之后）→ 要走这两步：

```
.venv/bin/python -m signal_map.scripts.build_deploy_seed
```

这会把本机的完整库重新裁成 35MB 的种子，然后提交到 GitHub。

**但是**：Railway 上那块硬盘里已经有库了，它**不会**被新种子覆盖（这是故意
的，否则客户数据会丢）。要让新数据生效，得先去 Railway 的 Volume 里删掉旧库
文件，再重新部署 —— 而这会同时清掉客户已有的会话。所以**上线以后再更新数据，
要先想清楚**。

---

## 几件必须知道的事

**后端只能开一个实例。** Railway 里不要把 replicas 调大。用的是 SQLite，同时
两个进程写会锁死，而且症状是偶尔报错、很难查。真的需要扩容，要先换成 Postgres
（Railway 上一键就能加，但代码要改）。

**35MB 那个种子库会进 Git。** 它是裁过的：完整库 176MB，砍掉了客户端永远读
不到的 43 万条关注边和 22 万个账号，接口结果逐项比对过，完全一样。

**种子库里没有客户的会话。** 故意清空的，免得把你开发机上的测试数据带到线上。

**Brief 码是随机串，不是 1、2、3。** 现在的码是 `xB14Ix6xrqbl`。要给新项目发
码，在库里新建 Brief 时会自动生成一个。

---

## 出问题了怎么看

- Railway 服务是红的 → 点进去看 **Deploy Logs**，最后几行一般会写原因。
- 网页打开是空的 / 报错 → 先单独访问 `Railway网址/api/meta`。
  - 那个也打不开 → 后端的问题，看 Railway 日志。
  - 那个正常 → 前端的问题，检查 Vercel 的 `SIGNAL_MAP_API` 有没有填对
    （要带 `https://`，结尾**不要**加斜杠）。
